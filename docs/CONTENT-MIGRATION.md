# 콘텐츠 이전 규칙

## 원문을 보존하는 방식

Notion을 요약·재작성하는 대신 렌더링 방식을 변경합니다. 소개·학력·활동·수상, 전체 프로젝트, 공개 기술 문서를 모두 목록화합니다.
현재 자리표시자는 이력을 주장하지 않으며 원문 수집 완료를 뜻하지 않습니다.
GitHub 공개 저장소 목록은 초기 후보 목록일 뿐, Notion의 전체 프로젝트 목록을 대신하지 않습니다.

1. 원본 페이지와 첨부파일을 저장소 밖의 로컬 작업 공간에 백업합니다.
2. 페이지별 제목·Notion URL/ID·상하위 관계·목표 경로·공개 확인일·이전 상태를 로컬 대조표에 기록합니다.
3. 각 하위 페이지·첨부파일도 독립적으로 공개 여부를 확인합니다. 부모 페이지 공개를 자식의 공개 승인으로 취급하지 않습니다.
4. 비공개 또는 확인 불가인 문서는 제외하고 보류 이유를 로컬 대조표에 남깁니다. 연결 도구로 읽을 수 있다는 사실은 공개 근거가 아닙니다.
5. 승인된 페이지는 문단·제목·표·코드·이미지·캡션·링크·프로젝트 문서 순서를 보존하여 Markdown으로 옮깁니다.
6. 공개 이미지·첨부만 `src/assets/`에 넣고, 임시 Notion 이미지 URL은 승인된 로컬 자산으로 교체합니다.
7. 이전된 페이지 간 링크와 앵커를 갱신하고 원문 대비 내용·파일 수를 대조합니다. 누락을 임의 문구로 채우지 않습니다.
8. 원문 URL 자체가 공개 가능한 경우에만 출처를 공개 front matter에 기록합니다.

## 페이지 구조

- `/about/`: 소개·학력·활동·수상. 내용이 길면 별도 하위 페이지를 추가하고 원문 관계를 유지합니다.
- `/projects/<slug>/`: 프로젝트 원문 전체. Juggernaut·JugGfx·JugNet·JugX 각각 독립 경로를 사용하고 관련 프로젝트를 연결합니다.
- `/notes/<topic>/<slug>/`: 프로젝트와 연결되는 공개 기술 문서. 개인 문서 전체를 자동 수집하지 않습니다.
- `/assets/<project>/`: 승인된 스크린샷·도식·첨부파일.

프로젝트 상세에는 원문에 있는 개요·기간·역할·환경·구현·문제 해결·결과·관련 문서를 보존합니다.
새로 붙이는 공통 필드는 제목·설명·분류·저장소 링크·공개 승인 상태입니다. 사실이 없는 항목은 만들지 않습니다.

## 프로젝트 문서 예시

아래는 필드 예시입니다. 실제 값과 원문 공개 여부를 확인한 뒤 사용합니다.

```yaml
---
layout: layouts/project.njk
title: 프로젝트 이름
description: 검증한 원문 설명
category: 라이브러리
permalink: /projects/example/index.html
visibility: public
publish: true
---
```

문서 페이지는 `layout: layouts/page.njk`를 사용합니다.
새 파일은 `src/projects/` 또는 `src/documents/` 아래에 추가하면 각 목록에 자동으로 포함됩니다.
분류·연도·카드 디자인과 상세 화면 연출은 원문 목록 대조 후 확정합니다.
