# Notion 자동 갱신

공개 Notion 포트폴리오를 **15분 간격**으로 읽고 검증한 뒤 GitHub Pages에 배포합니다. GitHub 예약 실행은 지연될 수 있습니다. 즉시 반영하려면 Actions의 `Verify and publish Pages`를 `publish: true`로 실행합니다.

## 반영되는 내용

- 소개 문구·본문, 얼굴 사진, 이메일·디스코드·GitHub·블로그 링크
- 현재 Education / Activity / Awards 구역의 내용과 항목 추가·삭제
- All 데이터베이스의 프로젝트 추가·삭제·제목·다중 분류·정렬 순서
- Pinned 태그가 있는 라이브러리와 게임의 대표 프로젝트 표시
- 프로젝트의 본문·제목·목차·표지와 이미지/GIF
- 발표 분류의 자료 목록

현재 공개 원본에서 프로젝트 18개, 본문이 있는 페이지 7개를 가져왔습니다. 본문이 비어 있는 원본은 기존 수동 본문을 유지합니다. 원본에 본문을 작성하면 그 내용이 우선합니다. 기존 URL은 유지하고 새 페이지는 Notion ID로 고정된 URL을 만듭니다.

본문의 문단·제목·서식·목록·인용·표·이미지·코드·토글을 변환합니다. 수식은 원본 TeX를 보존합니다. 지원하지 않는 블록은 해당 Notion 원문 링크로 표시하고 작업 로그에 남깁니다. 연결된 하위 페이지와 기술 블로그 전체를 재귀 복제하지 않으며 원문 링크를 유지합니다.

사이트의 배치·고정 제목·배경 이미지 목록은 디자인 설정입니다. 이 부분은 기존 스타일을 유지합니다. 새 배경을 추가하려면 `src/_data/hero.json`을 수정합니다. 선택한 세 프로젝트의 배경용 표지는 원본 표지 변경을 따라갑니다.

## 연결 방식과 공개 범위

`config/notion-sync.json`의 공개 사이트에 **로그인·쿠키·토큰 없이** 접근합니다. 비공개 연결 권한을 사용하지 않습니다. 공개 루트에서 도달할 수 있는 지정 블록과 All 데이터베이스의 공개 항목만 수집합니다. 응답에 섞인 상위 페이지 정보와 연결된 페이지 본문은 내보내지 않습니다.

공개 사이트가 사용하는 Notion 내부 API를 이용하므로 API 변경 시 수정이 필요할 수 있습니다. 네트워크·응답·이미지 수집 실패는 오류로 중단하고 이전 성공 배포를 유지합니다. 모든 자료 수집 후에만 로컬 파일을 갱신하며, 배포 전 공개 정책·동기화 테스트·빌드·링크 검사를 통과해야 합니다.

All에서 제거되거나 익명 접근이 불가능해진 프로젝트는 다음 성공 배포의 목록과 상세 경로에서 제외합니다. 루트 전체가 비공개로 바뀌면 동기화가 중단되므로 기존 배포는 별도로 내려야 합니다. 이미 공개한 Git 이력까지 삭제하는 기능은 아닙니다.

사진과 본문 미디어는 실제 파일로 저장합니다. 서명 URL·원시 Notion 응답·개인 메타데이터는 공개하지 않습니다. 공개 원본에 추가하는 내용은 다음 자동 배포에 들어갑니다.

## 운영

저장소 변수 `NOTION_SYNC_ENABLED=true`, `NOTION_AUTO_DEPLOY_ENABLED=true`로 활성화합니다. 전자는 수집, 후자는 예약 실행의 공개 배포를 제어합니다. 끄려면 해당 변수를 `false`로 바꿉니다. `NOTION_TOKEN`은 필요 없습니다.

배포에서 생성한 데이터는 Pages 산출물에 반영하며 소스 저장소에 자동 커밋하지 않습니다. 로컬도 최신화하려면 다음을 실행합니다.

```text
npm run sync:notion
npm run test:sync
npm run test:privacy
npm run check
```

새 동기화 항목은 `src/_data/notionSync.json`, 전체 목록은 `projectCatalog.json`에 저장합니다. 로컬 Markdown은 보존하고 동기화 데이터로 표시 내용을 덮어씁니다. 공개 여부를 판단할 수 없거나 지정 블록을 다른 페이지로 옮기면 실패하므로 설정을 검토합니다.
